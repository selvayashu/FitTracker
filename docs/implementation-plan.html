1. Overview

FitTrack records exercise (from Strava or entered manually), weight and meals. It computes BMI and a daily calorie allowance and produces reports on calories in versus calories out. It must be fully usable without Strava, work offline for meal and activity entry, and stay on free tiers.

Frontend
React, Vite, TypeScript, Tailwind, Recharts, vite-plugin-pwa
Edge / hosting
Cloudflare Pages plus Pages Functions / Workers for all secret-bearing logic
Backend
Supabase: Postgres, Auth, Row Level Security, cron, Edge Functions if needed
Delivery
GitHub repo, auto-deploy to Cloudflare Pages, four testable phases

3. Data model

Key constraints and indexes

  • activities.strava_id unique where not null; index on (user_id, start_time) for reports and duplicate checks.
  • meal_entries index on (user_id, date, meal_type).
  • CHECK constraints: duration 1-600, HR 40-220, quantity > 0, weight and height in sane ranges.
  • Client-generated UUID primary keys so offline writes are idempotent on retry.
  • daily_summaries refreshed by trigger on meal and activity changes, with a nightly cron backstop.

4. Design details

4.1 Calculation module (packages/shared)

Pure TypeScript with no framework imports. Used by the UI and the Workers, with Vitest boundary tests.

FunctionRule
bmikg / m², 1 decimal. Categories: Asian <18.5, 18.5-22.9, 23-24.9, ≥25. WHO option 25 / 30.
healthyRangeWeights giving BMI 18.5 to 22.9 at the user's height.
bmrMifflin-St Jeor: 10w + 6.25h − 5a, then +5 (male) or −161 (female).
tdeeBMR × 1.2 / 1.375 / 1.55 / 1.725 / 1.9.
calorieTargetTDEE ± 275 or 550. Floor = max(BMR, 1200 F / 1500 M); returns a warning flag when the floor applies.
dayAllowanceTarget + addback% × exercise kcal (default 50%).
macrosProtein 1.2-1.6 g/kg, fat 25-30% kcal, carbs remainder (4/4/9 kcal per g).
metKcalMET × kg × hours; result flagged estimated.
etaToTargetRemaining kg / pace per week, from 7,700 kcal ≈ 1 kg.
hrZonesZones 1-5 from % of max HR (default 220 − age, editable).

4.2 Security

  • RLS on every table, with policy tests that try cross-user reads and writes and expect failure.
  • The Strava client secret, webhook verify token, Resend key and Supabase service key exist only as Worker or Function secrets.
  • Worker endpoints verify the Supabase JWT. The webhook verifies the subscription token and looks up the user by Strava athlete ID.
  • OAuth state parameter ties the callback to the initiating user and prevents CSRF.

4.3 Offline and sync

  • The service worker precaches the app shell and caches food search results.
  • Meal and activity writes go to an IndexedDB outbox first, then replay on reconnect. UUIDs make replays safe.
  • The UI shows a pending-sync indicator. Conflicts are last-write-wins on manual rows, and Strava rows are read-only except notes.

4.4 Time

All timestamps are stored as UTC timestamptz. Display and "what counts as today" use Asia/Kolkata, so a day boundary is midnight IST.

8. Risks and mitigations

RiskMitigation
Strava rate limits (HTTP 429)Request queue with exponential back-off; sync in batches.
Duplicate calories between Strava and manual entriesOverlap detection (same type, ±30 min) and a keep-one review screen.
Offline replay creating duplicatesClient-generated UUIDs with upsert on insert.
Unsafe calorie targetsHard floor (1200 F / 1500 M / BMR) with a visible warning and the medical disclaimer.
Food data qualitySeed values reviewed against a reference table; users can add custom foods.
Free-tier limitsKeep sync batched, cache food searches, and use Edge Functions only if required.
Parallel agents diverging on typesSchema and types fixed in step 0; reviewer checks consistency.
